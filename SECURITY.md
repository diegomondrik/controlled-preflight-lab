# Security and Disclosure Boundaries

This is a synthetic laboratory, not a channel for reporting vulnerabilities in
real systems.

- Do not submit credentials, tokens, personal data, customer data, internal
  repository material, real exploit payloads, or confidential findings.
- Keep issue, pull-request, workflow, and check output synthetic and suitable
  for permanent public disclosure.
- Do not include local paths, private account details, billing information, or
  operational infrastructure identifiers.
- Do not test systems, accounts, or repositories outside the explicit
  laboratory scope.

If a real security issue is discovered, stop the public experiment and use an
already established private disclosure channel for the affected system. Do not
open a public issue containing the details.

No response-time or remediation commitment is made by this laboratory seed.
